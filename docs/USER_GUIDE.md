# AcadFlow User Guide

**Audience:** students, lecturers, platform members, department administrators, university administrators, super administrators, supervisors, group leaders, creators and support staff  
**Product snapshot:** 2026-08-15

AcadFlow brings academic coursework, submissions, attendance, research, publishing, communities, AI assistance and university administration together in one platform. What you can see depends on your role, university/department/course membership, subscription/entitlement, and whether an administrator has enabled the feature.

---

## 1. Before you start

### Supported account roles

AcadFlow has six main account roles:

| Role key | Display meaning | Typical purpose |
|---|---|---|
| `super_admin` | Super Admin | Platform-wide administration |
| `university_admin` | University Admin | Manage one university and its faculties/users/settings |
| `department_admin` | Department Admin | Manage a department, courses, lecturers, students and reports |
| `lecturer` | Lecturer | Teach courses, manage assignments/materials/attendance, review work and supervise research |
| `student` | Student | Learn, join courses, submit work, attend classes and use academic/research tools |
| `member` | Platform Member | Participate in Knowledge Hub, research, communities, groups and public academic ecosystem features |

Some responsibilities are not separate account roles:

- **Group Leader** — a user who leads a collaboration group.
- **Supervisor** — usually a lecturer assigned to a research/project supervision role.
- **Creator/Author** — a user who publishes Knowledge Hub content.
- **Event Organizer/Challenge Organizer/Judge** — contextual permissions in those modules.

### Availability can differ

AcadFlow administrators can place features in:

- **Enabled** — normal use;
- **Maintenance** — temporarily unavailable to normal users;
- **Disabled/Unreleased** — hidden or unavailable to normal users.

Administrators can preview restricted features for testing. Subscription plans can also limit some features.

## 2. Registration, login and onboarding

### Registration

If self-registration is enabled, choose **Register**, provide the required account information and complete email verification. Institutions may also create/invite accounts or import students.

### Login

Use your email/username and password. AcadFlow applies login rate limits and may require email verification or two-factor authentication before full access.

### Forgot password

Use **Forgot password** on the login screen. Follow the reset link sent to your email.

### Email verification

If the account is not verified, AcadFlow can show the verification screen and allow another verification email to be requested.

### Two-factor authentication

If 2FA is required/enabled, complete the challenge after login. You can manage 2FA and recovery codes from **Account Security**.

### Onboarding

Before normal application routes are available, new accounts complete role-aware onboarding. Depending on your account, onboarding can collect institution, faculty/department, programme/academic level, research/topic interests, skills, notification preferences and other profile information. Some optional steps can be skipped.

After completion, you are redirected to your role-specific dashboard.

## 3. Dashboard by role

### Student dashboard

Typically shows enrolled courses, pending assignments, submission activity, course progress, CGPA/performance information, invoices, groups and recent announcements.

### Lecturer dashboard

Typically shows assigned courses, student counts, assignments, submissions waiting for review, class performance, upcoming tasks and active attendance sessions.

### Admin dashboard

Super Admin, University Admin and Department Admin receive administrative statistics scoped to the access level, such as students, lecturers, courses, submissions and pending billing items.

### Platform Member dashboard

Shows personal Knowledge Hub publication activity, research projects, community/group participation, event registrations and challenge entries.

## 4. Courses and enrolment

### Students

Open **Courses** to view courses available to you. Depending on institutional settings, you may:

- enrol in eligible courses;
- join through an invitation/link/code;
- view enrolled course details;
- access assignments, materials, discussions and attendance for enrolled courses.

Course access is not granted just because you know a course URL; AcadFlow checks active enrolment.

### Lecturers

Lecturers work with assigned courses. Where enabled, a lecturer can self-assign only within allowed institution/department rules. Lecturer course invitations may also be used.

### Department/University administration

Admins manage course structure according to scope. Department admins can create/update department courses and assign lecturers. University/Super Admins have broader visibility based on policy and tenant scope.

---

## 5. Course materials

Course materials are files/resources attached to a course.

### Students

- open a course;
- select **Materials**;
- preview/download materials you are authorized to access;
- use the Material / Study Assistant when enabled.

### Lecturers

Lecturers can create, edit, publish and manage materials for assigned courses according to policy. Uploaded files go through the platform's media/security workflow.

### Material / Study Assistant

When enabled, this assistant can explain the current material, generate revision questions and connect concepts using authorized course context. It should not claim that unrelated facts are present in the material.

---

## 6. Assignments

### Students

From a course, open **Assignments** to see published tasks, instructions, requirements, due/close dates, attachments and rubric information when available.

The **Assignment Assistant** can help you:

- understand what the task is asking;
- break work into steps;
- understand concepts;
- build a self-checklist from instructions/rubric.

It is designed to support learning rather than replace your own graded work.

### Lecturers

Lecturers can create/manage assignments, requirements, attachments, publication state, deadlines, extensions and rubrics for authorized courses.

---

## 7. Submissions and grading

### Student submission workflow

A typical flow is:

```text
Open assignment
→ create/upload submission
→ review file/text
→ submit
→ lecturer review
→ correction request or grading/approval
→ resubmit if permitted
→ final result
```

AcadFlow can keep submission versions, comments and extension information. Late submissions/resubmissions depend on academic settings and task rules.

### Lecturer review workflow

Lecturers can open authorized course submissions, compare versions, comment, request corrections, grade, approve or reject according to policy and configured workflow.

### AI submission tools

- **Submission Validator** can analyze an authorized submission when configured.
- **Academic Integrity / Plagiarism** tools can perform configured similarity/integrity checks.
- AI results are assistance; institutional staff remain responsible for academic decisions.

## 8. Attendance

### Students

When a lecturer starts an attendance session, students may check in using the available method/QR flow. You can review your own attendance history.

### Lecturers

Lecturers can start/close attendance sessions for assigned courses, view records, edit permitted attendance data and export attendance.

### Administrators

Authorized admins can view/report attendance within their scope.

## 9. Course discussions

Discussions are course-based academic threads with replies, reactions/subscriptions and moderation/reporting.

The **Discussion Assistant** can:

- summarize viewpoints;
- identify unresolved questions;
- help draft a constructive response.

It does not impersonate participants or invent a consensus that is not present in the thread.

## 10. Groups and collaboration

AcadFlow groups support collaborative work beyond a single post/thread. Depending on permissions, users can create or join groups, invite/request members, manage tasks/resources and collaborate.

### Group Leader

A group leader can manage the group according to group policy, membership rules and course/tenant scope. Group Leader is a responsibility attached to a normal user account, not a separate login role.

## 11. Research Studio

Research Studio is the structured workspace for research projects and supervision.

A project can include:

- research type/workflow;
- structured sections;
- writing/version history;
- comments, approval and correction requests;
- meetings and reminders;
- tasks/action items;
- milestones;
- members/collaborators;
- literature search/references/notes;
- datasets;
- archives;
- amendments;
- export to HTML/PDF;
- specialized SIWES, seminar and project-defense workspaces;
- publication to Knowledge Hub when approved and enabled.

### Researcher/student/member

Create or join authorized research, write sections, respond to corrections, manage literature and track milestones according to your project membership.

### Supervisor/lecturer

A supervisor can review authorized projects, comment, request corrections, approve sections, schedule meetings, manage milestones and support specialized workflows. Supervisor is normally a contextual lecturer responsibility.

### Research Assistant

The assistant can help with research planning, methodology reasoning, evidence interpretation, revision and source-aware writing guidance using authorized project context. It must not invent sources, experiments, data or findings.

### Research Validator

The validator provides structured AI-assisted validation where enabled. Human academic review remains authoritative.

---

## 12. SIWES Workspace

SIWES lives within Research Studio when the `siwes_module` feature is enabled.

Possible records include:

- placement/organization;
- required/completed hours;
- logbook entries;
- attendance records;
- evaluations.

The **SIWES Assistant** can help improve reflection and report structure based on real recorded placement data. It must not invent attendance, hours, supervisors, employers or activities.

---

## 13. Seminar Workspace

The seminar module can manage seminar sessions, panel activity, questions/answers, scoring and completion workflow when enabled. Access and actions depend on research role/policy.

---

## 14. Projects and defense

Final-year/project workflows can connect submissions/research with defense scheduling and review.

The **Project Assistant** can help with structure critique, methodology reasoning, revision planning and defense preparation using authorized project context. It should not fabricate results/references or write an entire final project on the user's behalf.

## 15. Knowledge Hub

Knowledge Hub is AcadFlow's publishing and discovery ecosystem.

Users may be able to:

- discover/search publications;
- view creator profiles and leaderboards;
- create/edit/submit publications;
- bookmark/follow/react/comment/share;
- cite linked knowledge;
- join communities;
- follow learning paths;
- create/use reading lists;
- register for events;
- enter academic challenges;
- verify/download certificates;
- purchase premium resources where enabled.

Public access and institution/premium restrictions vary by publication.

### Publishing

Creators can draft content and submit it through the configured publication/moderation process. Approved Research Studio work can be published into a linked Knowledge Hub draft through the Research → Knowledge Hub feature.

### Publication Validator

AI can assist with publication quality/academic validation where configured.

### Knowledge Moderator

AI-assisted moderation can support human moderation. It does not replace administrator/moderator responsibility.

## 16. Grounded AI Companion

The Grounded AI Companion appears inside an eligible Knowledge Hub publication.

Its purpose is **“ask this publication”**, not general web search.

Typical pipeline:

```text
your question
→ check that the question is meaningful
→ search the current publication's indexed content
→ check evidence relevance
→ use the configured AcadFlow AI provider/rules
→ verify source citations
→ answer from the publication or say evidence is insufficient
```

Examples of good questions:

- “What are the main findings?”
- “Explain the methodology in simple terms.”
- “What limitations does the author identify?”
- “Which source section supports this conclusion?”

Meaningless input such as random keyboard strings should be rejected rather than sent to an expensive provider.

The companion does **not** automatically search the live open web. Using OpenAI/Gemini/Claude as the reasoning provider is different from web search; the publication remains the grounding source.

## 17. Main AI Assistant

The main AI Assistant is one interface containing specialized tools.

### Ask / Explain

- Student account → `study_assistant`
- Lecturer account → `lecturer_assistant`

### Improve Writing

Uses `writing_assistant`.

### Citation Review

Uses `citation_assistant`.

Each feature is routed through the same central AI settings. An administrator can configure the global provider/model or an intentional feature-specific override.

### Other contextual AI capabilities

```text

research_validator
assignment_assistant
siwes_assistant
project_assistant
material_assistant
discussion_assistant
knowledge_publication_validator

```

AI availability depends on AI Mode, feature-specific enablement, provider credentials and the central Feature Management state.

## 24. Notifications

All authenticated roles have a notification centre.

- view notifications;
- mark one or all as read;

## 25. Billing and subscriptions

Students/users can view eligible invoices, payments and subscriptions. Payment methods depend on gateways configured by administrators.

Admins can manage invoices/verification/waivers within their scope. University Admins can generate semester invoices. Super Admins manage subscription plans and platform-level payment gateways.

If your subscription does not include a feature, AcadFlow can block that feature even when the module itself is enabled.

## 26. Marketplace, wallet, payouts and refunds

When commerce is enabled, eligible Knowledge Hub/learning resources can be purchased. AcadFlow tracks orders/entitlements and can provide creator wallet/payout/refund workflows.

Depending on your role and plan, AcadFlow can generate/download documents and academic exports such as reports, transcripts/grade reports or research PDFs/HTML.

Administrators and lecturers can access reporting appropriate to their scope. Super Admin can access broader subscription analytics.

## 30. Department Admin guide

Department Admin focuses on a single department.

Typical responsibilities include:

- view department dashboard/stats;
- manage department courses;
- assign/remove lecturers and set coordinator status;
- view/manage users within permitted department scope;
- inspect submissions/attendance/reports;
- manage institutional billing within department scope;
- send notifications/announcements where permitted;
- manage assignment workflows;
- manage AI settings if granted by the role permission model, while platform-only controls remain restricted.

A Department Admin must not use student- or lecturer-only workflows by pretending to be that role; administrative preview and academic participation are separate concepts.

---

## 31. University Admin guide

University Admin manages one university across faculties/departments.

Typical responsibilities:

- university-scoped users and reports;
- faculty creation/editing;
- broader course/department oversight;
- university settings/overrides;
- institutional billing and semester invoice generation;
- AI settings where permitted;
- notifications and reports.

Platform-only feature release controls remain Super Admin responsibilities.

---

## 32. Super Admin guide

Super Admin is the platform-wide administrator.

Typical responsibilities include:

- universities and high-level institutional setup;
- subscription plans and subscription analytics;
- payment gateways and connection tests;
- student import tools;
- platform settings;
- **Feature & Module Management** for all 30 feature keys;
- permissions/audit-log views;
- central AI Settings, providers, routing, feature configuration and diagnostics;
- system-wide troubleshooting and maintenance.

### Feature & Module Management

For each registered module, Super Admin can choose Enabled, Maintenance or Disabled and can add a maintenance message/admin note. Dependencies are shown and enforced centrally.

### AI Settings

AI Settings control runtime AI behavior including operating mode, global provider/model, fallbacks, provider credentials/configuration, per-feature routes, guardrails, limits, health/diagnostics and grounded AI settings. Changes should affect the next AI request after cache invalidation; `.env` should not silently override a saved admin provider choice.

## 33. Platform Member guide

A Platform Member is not an institutional student/lecturer. The member dashboard emphasizes Knowledge Hub, research, communities, groups, events and challenges rather than course/submission/attendance workflows.

Members can only access institutional resources where a policy/explicit membership grants access.

## 34. Common messages and what they mean

### “Feature is under maintenance”

An administrator temporarily paused the module. Try again later.

### “Feature is unavailable/not released”

The module is disabled for normal users or a required parent feature is unavailable.

### “AI assistance is currently unavailable”

AI may be globally disabled, the specific AI feature may be disabled, or no valid provider/rule mode is available.

### “Not authorized” / 403

Your role, tenant, course membership, entitlement or policy does not permit the action.

### Session expired

Log in again. AcadFlow converts CSRF/session-expiration failures into a login redirect with an explanatory message for the web UI.

### A file will not preview/download

The file may be unavailable, blocked by security scanning, expired-token protected or outside your authorization scope. Ask your lecturer/admin if the content should be available.

---

## 35. Good AI usage in AcadFlow

- Give a clear academic question instead of random text.
- When using Grounded Companion, ask about the publication you are viewing.
- Treat AI output as assistance, not automatic academic truth.
- Check cited sources and original materials.
- Do not submit AI-generated text as your own where institutional rules prohibit it.
- Lecturers/admins should review AI grading/validation/moderation suggestions before making final decisions.

---

## 36. Getting help

Use the platform's Help/Documentation/Status public pages where available, contact your university/department administrator for account/course access issues, and contact the platform administrator for system-wide feature, payment gateway or provider problems.

When reporting an issue, include:

- your role;
- page/module;
- what you clicked;
- expected result;
- actual message;
- time of the problem;
- screenshot if it does not expose private information.

Do not share passwords, recovery codes, API keys or payment secrets in support messages.

## 37. Glossary

- **Feature Management** — central Enabled/Maintenance/Disabled control for modules.
- **Tenant** — an institution/university boundary used to isolate data/settings.
- **Grounding** — limiting an AI answer to supplied authorized sources.
- **Provider** — external/local AI engine such as OpenAI, Gemini, Claude, DeepSeek, Azure OpenAI or Ollama.
- **Rule Engine** — deterministic non-LLM logic used explicitly in Rule-Based/Hybrid paths.
- **SIWES** — specialized industrial work-experience workspace in Research Studio.
- **Entitlement** — permission to access purchased/premium content.
- **PWA** — installable Progressive Web App version of the website.
- **Submission version** — a saved revision/history record for submitted academic work.
- **Research archive** — sealed/exportable research state managed by Research Studio.

## 32. Updated course and academic workspace experience

Students use **My Courses** as the main course workspace. Course cards summarize the course and provide direct access to the individual course page. The course page brings together materials, assignments, discussions, attendance and recent course activity. Lecturers use their separate lecturer course-management view, while the individual course and academic-tool pages use the same modern workspace design where permissions allow.

### Materials

Students see only material they are allowed to access. Lecturers and authorized administrators can open and manage material for their courses, including their own hidden/draft-managed resources where appropriate. The individual material page shows file/resource details, course context, related activity and the Material / Study Assistant when enabled.

### Assignments, discussions and attendance

Assignment pages show status, requirements, timing, attachments/rubrics and the user's current submission workflow. Discussion pages preserve search/filtering, replies, reactions, subscriptions, reporting/moderation and the Discussion Assistant when enabled. Attendance pages clearly separate student check-in/history from lecturer session creation, QR/geofence management, records and exports.

## 33. Updated Knowledge ecosystem experience

Communities, groups, learning paths, reading lists, events, challenges, leaderboard and creator profiles now use a more consistent responsive workspace design. Existing membership, visibility, moderation, enrollment/registration, voting/judging and creator privacy rules still apply.

### Publication creator workspace

If you create a Knowledge Hub publication, **Open workspace** remains available for your publication even when its current workflow state is read-only. For example, a publication under moderation can still be opened so you can see its content, status and moderator feedback. Editing and **Submit for moderation** are shown only when the current status allows those actions (such as draft, changes requested or rejected). This prevents the author workflow from incorrectly showing Access Denied simply because editing is temporarily locked.

## 34. AI provider connection messages for administrators

Super Admins managing provider configuration can use **AI Settings → Test Connection**. A failed test now distinguishes problems such as authentication, model/endpoint mismatch, TLS certificate failure, DNS failure, connection refusal, rate limiting, timeout and other network errors instead of labeling every transport failure as a timeout. The result includes a safe request identifier and diagnostic without displaying API keys. More detailed operational information is written to `storage/logs/ai-provider.log`.



## AI provider connection diagnostics (updated 2026-08-18)

When an administrator uses **AI Settings → Providers → Test Connection**, AcadFlow now records a safe request ID and diagnostic in `storage/logs/ai-provider.log`. Network failures, TLS problems, provider authentication/model errors and rate limits are shown separately. Provider request payloads are sent as explicit JSON. If an installation still contains a Gemini 1.5/2.0 model ID that Google has already retired, AcadFlow maps that retired ID to a supported replacement while leaving other administrator model choices unchanged.
