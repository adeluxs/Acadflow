# AcadFlow Technology Stack

**Current source snapshot:** 2026-08-15  
**Canonical overview:** `DEVELOPER_GUIDE.md`

This file documents the stack actually present in the current AcadFlow source. It replaces older planning assumptions.

## Backend

| Component | Current implementation |
|---|---|
| Language | PHP `^8.2` |
| Framework | Laravel `^12.40` |
| ORM | Eloquent |
| API auth | Laravel Sanctum `^4.3` |
| PDF generation | `barryvdh/laravel-dompdf ^3.1` |
| PDF parsing | `smalot/pdfparser ^2.12` |
| CLI/debug | Laravel Tinker, Pail |
| Tests | PHPUnit `^11.5`, Mockery |
| Formatting | Laravel Pint |

## Database

- `.env.example` recommends **MySQL**.
- Migrations include explicit MySQL identifier-safety checks because composite autogenerated names previously exceeded MySQL's 64-character identifier limit.
- Database is also used for sessions/cache/queues by bootstrap default, but these stores are configurable.

## Cache / queue

- Laravel cache supports database and Redis among normal framework stores.
- Queue connections include sync, database, Redis, Beanstalkd and SQS through Laravel configuration.
- AcadFlow actively uses `default`, `ai`, `indexing`, and `analytics` queues.
- Production Redis is recommended where hosting supports it; Horizon is **not** installed in the current Composer dependencies.

## Frontend

| Component | Current implementation |
|---|---|
| Main rendering | Blade |
| CSS | Tailwind CSS `^3.4.13` |
| Build | Vite `^6.0.11` |
| HTTP JS | Axios |
| Vue | Vue `^3.4.0` for selected components |
| Rich editor | Lazy-loaded Quill 2.0.3 + fallback editor |

AcadFlow is not currently an Inertia/Livewire SPA architecture. Do not add those assumptions to documentation unless the source changes.

## Files/media

- Laravel Flysystem abstraction
- local disk by default; S3-compatible configuration supported by Laravel config
- centralized media security, malware scanner adapters, expiring delivery tokens and secure download services

## AI

- centralized provider architecture under `app/Ai` and `app/Services/Ai`
- providers: Rule-Based Engine, OpenAI, Claude/Anthropic, Gemini/Google, DeepSeek, Grok/xAI, Azure OpenAI, Ollama
- runtime provider/model selection is database/admin-driven through `AiRuntimeConfigService` and `AiRouter`
- local search/indexing uses `SearchDocument`, `SearchChunk` and `LocalEmbeddingService`

## External scholarly discovery

Configuration exists for ORCID, OpenAlex, Crossref, Semantic Scholar, CORE, DOAJ, PubMed and arXiv through the scholarly service layer. Availability depends on provider configuration/API access.

## Payment/commerce

- provider abstraction via `GatewayInterface`/`PaymentGatewayManager`
- current concrete payment gateway adapter: Paystack
- separate marketplace/wallet/payout/refund models and services

## PWA

- manifest/service worker/offline assets are included
- runtime availability is controlled by Feature Management (`pwa_enabled`)

## Development prerequisites

- PHP 8.2+
- Composer 2
- Node.js/npm
- MySQL

- Git
