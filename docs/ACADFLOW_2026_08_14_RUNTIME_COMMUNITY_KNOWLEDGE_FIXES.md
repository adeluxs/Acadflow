# AcadFlow Runtime, Community & Knowledge Hub Fixes — 2026-08-14

This patch builds on the existing AcadFlow architecture. It does not replace the media, notifications, Knowledge Hub, community, or Research Studio subsystems.

## Runtime fixes

### 1. Flysystem `file_size` metadata exception

The failure came from Laravel/Flysystem `download()` / `response()` paths requesting object size metadata while serving media. Some adapters or missing/orphaned files cannot return that metadata and throw `UnableToRetrieveMetadata`.

Changes:

- Added `App\Services\Media\SafeFileDeliveryService`.
- Media previews and secure downloads now use streaming reads and do not require `file_size` metadata.
- Missing objects return a controlled 404; temporary storage/provider failures return a controlled 503 instead of a raw 500.
- Secure download tokens are not consumed until the file has been successfully opened.
- Uploads are verified with the configured storage adapter before a `media_assets` record is created.
- Course-material downloads, submission downloads/previews, submission-task attachments, research archives and certificates now use the same safe stream path.
- Removed direct `Storage::size()` usage from generated-document workflows. PDF sizes are recorded from the generated byte string.
- Generated submission PDFs now use the configured Laravel disk instead of assuming the legacy `storage/app/...` path. This is important because the current local disk root is `storage/app/private`.

Existing database rows that point to a file that has already been deleted cannot be reconstructed by source code. They now fail safely; the missing file should be re-uploaded.

### 2. Knowledge Hub Blade parse failure

`resources/views/knowledge/show.blade.php` was rebuilt with clearly nested, multi-line Blade directives. The feature set remains intact: protected access, purchase controls, files, bookmarks, follow, reactions, sharing, discussion, citations, reporting and grounded AI companion.

### 3. Research Studio Blade parse failure

`resources/views/research/workspace.blade.php` was rebuilt with explicit, reviewable Blade nesting. Existing milestones, tasks, meetings, attendance, action items, collaborators, archives and amendment workflows remain connected to their original routes.

### 4. Notification `MethodNotAllowedHttpException`

The notification page posted to PUT/DELETE routes without HTML method spoofing.

Fixed:

- Mark all read → `@method('PUT')`
- Mark one read → `@method('PUT')`
- Clear all → `@method('DELETE')`
- Static notification routes are declared before `{notification}` routes to avoid path ambiguity.

## Community post fixes and redesign

- Poll inputs are validated only when `post_type=poll` using `exclude_unless`.
- Blank poll inputs are trimmed/filtered before poll validation.
- Poll choices must be distinct and a real poll still requires at least two choices.
- Non-poll posts no longer fail because hidden/blank poll controls exist in the form.
- The composer now has interactive post-type controls for Discussion, Announcement, Resource, Event and Poll.
- Poll inputs appear only for polls and can be added/removed dynamically up to the existing 10-option server limit.
- Added post character counter, clearer validation feedback, richer post cards, pinned state, moderation state and poll progress percentages.
- Community hero, membership area, members sidebar, invitations, rules and reporting were visually modernized without replacing the existing models/routes.

## Knowledge Hub redesign

- New modern discovery hero and search experience.
- Uses the existing recommendation service to surface recommended next reads.
- Improved resource cards with type/access/status context, reading time, author and engagement signals.
- Updated Knowledge Hub navigation.
- Publication detail page redesigned with clearer author/provenance, engagement, protected access, resources, discussion, citation impact and grounded AI companion areas.
- File sizes displayed from persisted `size_bytes`; the interface does not query live storage metadata just to render a page.

## Regression safeguards

Added:

```bash
php scripts/check-runtime-regressions.php
```

The preflight currently checks all Blade templates for block nesting and prevents reintroduction of:

- direct `Storage::size()` metadata access,
- direct Flysystem `download()` / `response()` serving in application code,
- unconditional community poll validation,
- missing notification method spoofing.

Also run:

```bash
php scripts/check-mysql-identifiers.php
```

## Deployment / local refresh

After replacing the source, run from the project root:

```bash
php artisan optimize:clear
php artisan view:clear
php artisan route:clear
php artisan config:clear
php artisan migrate
npm install
npm run build
```

If dependencies already exist and `package-lock.json` has not changed, `npm ci && npm run build` is also appropriate.

No new database migration is required by this patch.
